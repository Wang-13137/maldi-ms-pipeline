# maldi-ms-pipeline

[![CI](https://github.com/Wang-13137/maldi-ms-pipeline/actions/workflows/ci.yml/badge.svg)](https://github.com/Wang-13137/maldi-ms-pipeline/actions/workflows/ci.yml)

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

MALDI-TOF 质谱代谢组学分析流水线：从原始谱图到可用的诊断特征面板。
代码由一份跑了半年的分析脚本整理而来，把散落的常量、重复的逻辑和一次性
的绘图代码拆成可配置、可测试的模块。

---

## 1. 背景与要解决的问题

尿路感染（UTI）的临床确诊依赖尿培养，通常需要 24-48 小时。MALDI-TOF 质谱
已经在微生物鉴定上普及，仪器产出一条谱图只要几分钟；如果代谢指纹里存在
能区分感染与健康样本的信号，就有可能把"等两天"压缩到"等几分钟"。

本项目处理的是深圳大学一组真实临床样本：**37 例尿液样本（感染 8 例 /
健康 29 例）**，每例 211,407 个数据点，合计约 780 万数据点，另附 3 个阴性
对照。原始谱图是 profile spectrum（连续轮廓谱），不是已经抽好的峰列表。

要解决的问题有三层：

1. **从轮廓谱里可靠地找峰。** 仪器输出的强度曲线里绝大多数起伏是噪声。
   峰检测放宽一点，假峰就会淹没后续分析；收紧一点，弱信号又全丢了。
2. **把 37 条谱图的峰对到同一套特征上。** 同一个分子在不同样本里的实测
   m/z 会漂几十 ppm，不做对齐就是 37 套互不相干的特征。
3. **在 37 例样本上做建模，并诚实报告它有多可信。** 这是样本量决定的硬
   约束，见第 6 节。

## 2. 算法链

每一步都写清「为什么这么做」，而不只是「做了什么」。

### 2.1 读取与分组（`src/maldi_ms/io.py`）

每个 Excel 文件第一列是 m/z 轴，其余每列一条谱图。样本身份只能从列名解析
（`样品2_UTI11`、`样品10__CN`、`样品19_阴性对照`），所以分类放在读取层，
下游不必再关心文件来源。感染组编号写在配置里，不在代码里。

### 2.2 SG 平滑（`preprocessing.py`）

Savitzky-Golay 平滑，窗口 41 点（约 0.06 Da），二阶多项式。

**为什么**：profile spectrum 在峰顶附近存在高频抖动，直接按局部极大值找峰
会检出大量假峰。SG 平滑用局部多项式拟合代替局部平均，在压掉高频噪声的同时
保留峰形和峰位置——这一点比移动平均重要，因为后面要按峰形算质心和面积。
窗口取 41 是折中：再大峰会被压平、相邻峰会粘连，再小则噪声去不干净。

基线校正和 TIC 归一化实现了但默认关闭。MALDI 谱的基线漂移通常不明显，
且这两步会改变峰面积的量纲；需要时再打开。

### 2.3 残差 MAD 噪声估计（`peak_detection.py`）

`noise = 1.4826 * MAD(raw - smoothed)`。

**为什么不能用全谱标准差**：真实峰会把它抬高好几倍，SNR 阈值随之水涨船高，
弱峰全部漏检。用平滑残差是因为残差里几乎只剩下噪声。

**为什么用 MAD 而不是标准差**：MAD（中位数绝对偏差）对少量大残差不敏感。
残差在峰位置会出现个别大值，标准差会被它们拉偏，MAD 不会。1.4826 是
MAD 到正态分布标准差的换算系数。

### 2.4 SNR ≥ 3 顶点检测

在平滑谱上找 prominence ≥ `noise * 3` 的局部极大值，相邻峰间距 ≥ 0.2 Da。

**为什么用 prominence 而不是高度**：prominence 衡量的是"这个峰比周围高出
多少"，即局部突起程度；height 衡量的是绝对强度。在基线整体抬高或存在
宽包的区域，height 会把一段缓慢起伏误判成峰，prominence 不会。

**为什么是 3**：Bruker flexAnalysis 的默认值。SNR=3 对应约 99.7% 的
单尾置信度，是"宁可多检、靠后处理筛"的取向；配套的筛选在 2.6 节。
本项目试过 SNR=5，特征数膨胀、AUC 虚高，已弃用，见第 6 节。

0.2 Da 的间距来自 MALDI-TOF 10000-20000 的分辨率：比这更近的两个峰在
物理上无法分辨，同时检出说明其中一个是噪声或肩峰。

### 2.5 质心定位与峰面积积分

在峰区间内用强度加权平均 m/z 作为峰的 m/z，用区间强度和作为定量值。

**为什么不用顶点 m/z**：顶点受采样网格限制，且峰形不对称时会系统性偏移。
质心法对网格和噪声都不敏感，是商业软件的通行做法。

**为什么用面积而不是顶点高度**：MALDI 的离子化效率波动很大，同一分子的
峰高在重复点样之间能差一倍；峰宽展宽时面积比高度稳定得多，因此定量用面积。

峰边界的判定是：从顶点向两侧走，强度降到顶点 10% 或开始回升即停，
最大搜索半径 0.05 Da。

### 2.6 五重质控

| 质控项 | 阈值 | 剔除什么 |
| --- | --- | --- |
| 峰宽 | ≥ 3 个数据点 | 单点噪声尖峰 |
| 真实 SNR | ≥ 3 | 显著性不足的弱峰 |
| 绝对强度 | apex ≥ 600 | 探测器噪声本底附近的信号 |
| 相对强度 | ≥ 基峰的 0.01% | 与基峰差 4 个数量级、定量不可信的信号 |
| 质心位移 | ≤ 0.05 Da | 峰形严重不对称（多半是重叠峰）的定位错误 |

**为什么要五重**：SNR 只保证"高于噪声"，不保证"是真实的峰"。单点尖峰的
SNR 可以很高；峰形不对称说明质心不可信。这几条来自 flexAnalysis 的
默认后处理，逐条加上之后假峰从约 50 个降到 0（见 2.7 的 UTI11 验证）。

### 2.7 同位素去除

在 +1.003355 Da 和 +2.00671 Da 处以 10 ppm 窗口搜索，若子峰与母峰强度比
落在 (0.01, 0.9) 内，判定为同位素峰并剔除。

**为什么必须做**：同位素峰会被当成独立代谢物，虚增特征数，还让同一分子的
信息在模型里重复计权。10 ppm 的窗口远小于对齐用的 100 ppm，是因为同位素
间距是物理常数，实测偏差只来自质量精度。

**UTI11 单样本验证**：108 个候选峰，经过上述流程后保留 16 个，人工核对
0 个假峰。对照的旧版算法（顶点法、无峰宽质控）在同一条谱上保留大量噪声峰。

### 2.8 100 ppm 跨样本对齐（`alignment.py`）

按 m/z 排序后单遍扫描：与当前簇的中位数比较 ppm 偏差，落在容差内就并入
并更新中位数，否则开新簇。

**为什么用 ppm 而不是固定 Da**：MALDI-TOF 的质量误差随 m/z 近似线性增长。
100 ppm 在 m/z 100 处是 0.01 Da，在 m/z 900 处是 0.09 Da。固定 Da 窗口
在低质量端会把相邻代谢物错误合并，在高质量端又会漏合并。

**为什么用中位数而不是均值**：个别离群的 m/z 不会把簇中心拽走。

本项目早期用过"ppm 与 Da 双判据"，在低 m/z 区造成过合并（多个代谢物被
塞进一个特征），改成纯 ppm 后消除。`configs/uti8_50.yaml` 里保留纯 ppm 配置。

### 2.9 阴性对照背景过滤（`filtering.py`）

MALDI 基质（CHCA、DHB）本身在低质量区产生大量峰，塑料耗材和溶剂也会带来
污染物。判据是：对照里没检出的特征直接保留；样本最高强度超过对照 2 倍的
也保留（说明样本里确有额外来源）；其余情况下若对照强度高于样本中位强度的
50%，判为背景剔除。

**为什么要留 2 倍这个口子**：对照里存在不等于样本里的信号全部来自污染。
真实代谢物可能在对照里也有痕量本底，一刀切会误删真信号。

### 2.10 检出率过滤

要求特征至少在 15% 的样本（37 例里至少 5 例）中出现。

**为什么**：只在一两个样本里出现的特征，既可能是随机的离子化波动，也会在
交叉验证里造成训练折与测试折之间的分布漂移。15% 是把"偶然出现"与"稳定
存在"分开的最低门槛——再高会砍掉只在感染组出现的稀有标志物，而那正是
要找的东西。

### 2.11 变换、差异检验与建模（`modeling.py`）

峰面积动态范围跨 3-4 个数量级且严重右偏，先取 `log10(x + 1)` 把乘性差异
变成加性差异。缩放按每列的 `sqrt(std)` 而非 `std`：MALDI 峰面积的方差与
均值强相关，用 std 缩放会过度放大低丰度特征的噪声，`sqrt(std)` 是折中。

差异检验用两组 t 检验（log 空间），BH 法做 FDR 校正。

特征选择用随机森林重要性排序，再逐个 panel 规模（3 / 5 / 10 / 15 / 20 /
30 / 50 / 80）评估 SVM（RBF 核）的 5 折分层交叉验证 AUC，取最优。用 RF 排序
而不是直接用 p 值排序，是因为 RF 能捕捉非线性与交互作用；同时也算了 t 检验
排序的对照曲线，两条曲线都在输出里。

**为什么用 5 折分层 CV**：37 例里感染组只有 8 例，留出法一次划分的结果方差
极大。分层保证每折两组的比例与总体一致。

原始数据是未公开的临床样本（原因见下面「数据说明」）。clone 之后不需要
任何数据，就可以先验证仓库能跑、算法逻辑正确：

```bash
pip install -e ".[dev]"

# 方式一：测试套件（16 个用例，含合成数据的端到端冒烟）

python examples/quickstart.py
```

### 数据说明

本仓库**不包含原始谱图数据**。数据是一组真实临床尿液样本（37 例 + 3 个
阴性对照），来自医院合作项目，样本信息未获授权公开。因此第 5 节的数字
无法在 clone 后直接复现，其可信度由两件事支撑：测试套件验证算法逻辑，
输出与原始脚本逐格比对（最大绝对差 0）。

如果你有同格式的数据（Excel 文件，第一列为 m/z 轴、其余每列一条谱图，
列名含 `UTI<n>` 编号），换上即可运行。

### 用真实数据运行

一键跑通全流程：

```bash
python -m maldi_ms.cli --config configs/uti8_50.yaml \
    --data <你的数据目录> \
    --out outputs/uti8_50
```

在 Windows 上建议带上环境变量，避免中文输出编码问题：

```bash
PYTHONIOENCODING=utf-8 python -m maldi_ms.cli \
    --config configs/uti8_50.yaml \
    --data <你的数据目录> \
    --out outputs/uti8_50
```

分步调用（想改中间环节时用这个）：

```python
from maldi_ms import alignment, filtering, modeling

from maldi_ms.peak_detection import pick_peaks

cfg = load_config("configs/uti8_50.yaml")
dataset = read_directory("<你的数据目录>", cfg)

names = sorted(dataset.samples)
peaks = {n: pick_peaks(dataset.samples[n].mz, dataset.samples[n].intensity, cfg)[0]
         for n in names}
```

更完整的示例见 `examples/quickstart.py`：

```bash
python examples/quickstart.py <你的数据目录>
```

## 6. 已知局限

这一节是这份仓库可信度的来源，不回避任何一条。

**1. 样本量只有 37 例，感染组 8 例。** 这是最根本的约束。0.9167 的 AUC 是
5 折交叉验证的结果，不是独立测试集的结果。8 例阳性样本意味着单个样本的
去留就能显著改变决策边界，也意味着任何 panel 规模都只能取到 3-5 个特征——
再多就过拟合。这个数字应当读作"值得继续做下去"，而不是"模型已经可用"。

**2. 4 个差异特征的 p < 0.05，但 FDR 校正后全部不显著（最小 FDR = 0.552）。**
47 个特征同时做检验，多重比较是必须校正的。FDR = 0.552 的含义是：在这 4 个
特征里，期望有约一半是假阳性。换句话说，单变量统计层面**没有找到**可靠的
差异代谢物。AUC 0.9167 来自多变量模型，与这些单变量检验并不一致——
这种不一致在小样本上很常见，但也正是需要更多样本才能分辨的地方。

**3. PLS-DA 置换检验 p = 0.42，未通过。** 作为对照，本项目跑过 PLS-DA 与
200 次置换检验，p = 0.42 远未达到显著水平（通常要求 p < 0.05）。这说明
"两组之间存在可分离的代谢模式"这一假设在这批数据上没有得到验证。
OPLS-DA 得分图看起来有分离，是监督方法在小样本上的必然结果，不能作为证据。

**4. PCA 前两主成分只解释 28.5%，两组不分离。** 无监督的 PCA 在 PC1-PC2 平面上
感染组与健康组完全重叠。代谢组学数据里这通常意味着：组间差异小于个体间
差异（年龄、饮食、用药、取样时间的差异都压过了感染信号）。

**5. 曾出现过特征膨胀与 AUC 虚高的配置，已弃用。** 在 SNR ≥ 5 且不设绝对
强度阈值的一版配置下，特征数膨胀到 316，AUC 达到 1.000。AUC = 1.000 在
37 例样本上不是好结果，是过拟合的直接证据：特征数远大于样本数时，模型
总能找到完美区分两组的组合。该配置不进仓库，默认配置固定为 47 特征 /
AUC 0.9167。默认参数（SNR = 3、强度 ≥ 600、100 ppm、检出率 15%）写在
`configs/uti8_50.yaml` 里，改任何一个都会改变最终结果，改之前请先看这一节。

**6. 没有做代谢物鉴定。** 47 个特征只有 m/z 值，没有对应的代谢物名称。
m/z 212.92 是什么分子，需要 MS/MS 或者标品比对才能确定。在这之前，
"诊断 panel"只能是统计意义上的特征组合，不具备可解释的生物学含义。

**7. 批次效应未完全消除。** 37 例样本分布在 3 个 Excel 文件里（对应不同的
上机批次），每个批次各带 1 个阴性对照。阴性对照过滤能去掉基质峰，但
仪器状态漂移带来的系统性强度差异没有专门的校正方法。

**8. RF 特征选择在全量数据上完成，panel AUC 存在乐观偏差。** 第 2.11 节的
评估流程是：先用全部 37 例样本拟合随机森林、得到特征重要性排序，再按排序
取 Top-N 做 5 折 CV。特征选择阶段已经"看过"测试折里的样本，这是一处
信息泄漏——0.9167 应当读作偏乐观的估计。无泄漏的做法是嵌套交叉验证
（特征选择在每一折的训练集内部完成），这是本仓库最明确的后续改进方向。
之所以保持现状：它与原始分析脚本的流程一致，仓库的定位是忠实复现。

```
maldi-ms-pipeline/
├── README.md
├── pyproject.toml
├── .gitignore
├── configs/uti8_50.yaml        # 全部可调参数，代码里没有魔法数字

│   ├── __init__.py

│   ├── preprocessing.py        # SG 平滑、基线校正、归一化
│   ├── peak_detection.py       # 噪声估计、SNR 顶点检测、质心、五重质控、同位素
│   ├── alignment.py            # 100 ppm 跨样本特征对齐
│   ├── filtering.py            # 阴性对照背景过滤、检出率过滤
│   ├── modeling.py             # 变换、差异检验、RF 选择、CV 评估
│   └── cli.py                  # 命令行入口与流程编排
├── tests/                      # pytest，16 个用例
└── examples/quickstart.py      # 分步调用示例
```

所有参数集中在 `configs/uti8_50.yaml`。改参数不需要改代码。

## 8. 测试

```bash
python -m pytest tests/ -q
```

16 个用例，覆盖四类：

- **峰检测正确性**：合成高斯峰在已知位置被检出，定位误差 < 0.05 Da；
  纯噪声谱不产生峰；同位素峰被剔除而母峰保留。
- **噪声估计鲁棒性**：注入 1% 极端异常值后 MAD 估计漂移 < 20%，
  普通标准差则被抬高 5 倍以上；残差法不被真实峰污染。
- **对齐逻辑**：相差 80 ppm 的两个 m/z 合并，相差 5000 ppm 的不合并；
  同样的 0.01 Da 偏差在低质量端合并、高质量端不合并（验证 ppm 的相对性）。
- **端到端冒烟**：6 例合成样本跑通全流程，断言输出形状、文件齐全、
  指标自洽，不锁定具体数值。
